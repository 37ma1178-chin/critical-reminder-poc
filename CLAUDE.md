# RV configurator (India)

Proof-of-concept for a camper / motorhome configurator: requirements → eligible vehicles → 2D layout → 3D. 14 base vehicles (Force Traveller N, Traveller 26, Urbania, Tata Winger, and three bus chassis).

## Files
- `data/handover/` — the research handover (3 zips, unzipped as-is, **read-only; never edit**). Part 1: vehicle data, GLBs, interior confidence report, research reports, open questions. Part 2: official rule PDFs, text extracts, `rules_summary.md`. Part 3: the South Africa-hosted Urbania brochure. Cite files in here by path.
- `data/vehicles/<id>.json` — **the single source of truth for every vehicle dimension (mm)**, one file per variant, generated by `tools/import_handover.js`. Every number is `{ value, unit, confidence (CONFIRMED / ESTIMATED / UNKNOWN), source, method?, expected_error? { minus, plus, text }, alt_estimates? }`. `index.json` lists the variants. `body` = OEM exterior figures; `interior` = living-area estimates with error bands; `exterior_profile` = side-profile shape (Force side render for the Urbania, the handover's GLB build rule otherwise); `stock_seating` only for the Urbania 4400 (matched to the Force 16+D render). `URBANIA_RECONCILIATION.md` lists every Urbania difference between the India brochure (wins) and the handover.
- `data/reference/builders/` and `data/builders/azad_automotive_customs.json` — body builder evidence. Azad Automotive Customs' Urbania 4400 decks (Aug and Oct 2026): dimensioned layouts, seat and module specs, prices (builder_quoted, 60-day validity), and the rear air-suspension kit. Confidence classes: **BUILDER_MEASURED** (a builder's dimensioned drawing of a built vehicle, between CONFIRMED and ESTIMATED) and **BUILDER_SPEC** (a builder's product sheet).
- `data/rules.json` — the rulebook: LEGAL (pass/fail, each rule with document + clause + how it was checked), CONVERSION (questionnaire gates), DESIGN (DESIGN STANDARD, never legal; aisle fail < 300, warn 300–400, ok ≥ 400), STATE (Kerala, Maharashtra, Goa; commercial use only) and `pending` (open questions, never resolved by assumption).
- `data/design_catalog.json` — footprints the space check uses (seat tiers, beds, washrooms, kitchen, storage), each labelled CATALOG / RENDER / HANDOVER-GLB / BUILDER_SPEC / DESIGN DEFAULT.
- `js/eligibility.js` + `tools/eligibility.js` — questionnaire (`data/questionnaires/*.json`) → ELIGIBLE / REJECTED / UNDECIDED per vehicle and seat tier. UNDECIDED names the estimated dimension and its band; fits on the estimate but not at the low end = UNDECIDED. `node tools/eligibility.js data/questionnaires/test_A.json`. `node tests/run_specs.js` checks the hard expectations; results are kept in `tests/results/`.
- `data/reference/urbania-17-render-scaled.json` — the old single-vehicle file, kept only as an input to the importer (render-scaled Urbania values). Not loaded by any page.
- `data/reference/` — the Force Motors Urbania DX brochure (PDF + its spec page as PNG), the top-view and side-profile renders the layout was matched to, and the annotated measurement image. The brochure has no interior dimensions; the interior floor area shown in the panels (≈7.7 m² behind the cab) is derived from the estimated cab depth and wall thickness.
- `data/components.json` — catalog of camper conversion modules (partition, crew bunk, kitchenette, fridge, lounge bench, toilet cubicle + toilet unit, water tank, electrical cabinet, TV). Each has an installed `footprint` (length along x, width along y, height), the bare `product` size where relevant, an Indian-market `price_inr` range, a `confidence` flag and `sources`. `layout_rules` gives the module order from the partition and the gap between zones.
- `js/vehicle.js` — `Vehicle.load(id)` loads `data/vehicles/<id>.json` (no id = `force_urbania_4400wb`) and `data/components.json`; `toSpec()` unwraps the provenance objects into plain numbers and keeps them in `spec.provenance[path]` (`Vehicle.confidence(spec, 'body.front_overhang')`). It derives all shared geometry once (`{ spec, layout, components, camper }`). Track is UNKNOWN for most variants: wheels are then drawn flush with the body side (`layout.trackKnown = false`). `Vehicle.list()` / `mountPicker()` drive the vehicle picker; the vehicle id travels in the URL as `vehicle=`. Shared geometry: axle positions, interior box, wheel rectangles and housings, the full list of seat rectangles, and the camper zones (`camperZones`) laid out rear-wards from the partition. `camperPlacements(spec, catalog, selection)` turns a module selection into one rectangle per module (zone modules against their `side`, sub-modules by their `placement`), which is what every view draws. `priceRange` / `componentPrice` sum catalog prices. Both views draw from this, so they cannot disagree. Vehicle frame: x = 0 at the rear bumper increasing to the front, y = 0 on the centreline increasing to the right (driver) side.
- **Module selection lives in the URL query** so both pages show the same configuration: `?layout=camper&modules=a,b,c&tv=43&fridge=built_in&toilet_unit=portable&view=topdown` (`Vehicle.readSelection` / `writeSelection` / `selectionQuery`; `view` is the 3D camera preset). Zones are fixed: a module that is off leaves its bay empty. A sub-module with `requires` is dropped when its parent is off.
- `index.html` — 3D viewer (Three.js r128 via jsdelivr UMD). Cutaway / roof-off / full exterior views, stock 17-seat layout, lounge (still a placeholder preset), camper conversion with a per-module checklist (price range + confidence badge, variant selects, running total). Converts mm → m; scene x = vehicle x − length/2, scene z = vehicle y. **Roof off is the bird view, the detailed one:** the camera fits the vehicle from overhead, tops that hide things (cubicle lid, upper bunk) go see-through, and every seat, module, wheel housing, empty bay and the walkway gets an HTML label chip with its name and size (`refreshLabels`, projected each frame). Label names come from `short_name` in the catalog.
- `topview.html` — dimensioned 2D top-view SVG for any of the 14 vehicles (picker in the panel), 1 unit = 1 mm. Front points right, driver side is down the page. Stock seating or, with `layout=camper`, the selected camper modules as labelled rectangles (dashed = empty bay) with a read-only module list and a link back to the configurator.
- `sideview.html` — dimensioned 2D side-profile SVG for any of the 14 vehicles (left side, entry door), 1 unit = 1 mm, front points right. The outline, glazing, cladding, doors and wheels come from `Vehicle.sideProfile(spec)`, which uses the brochure numbers plus `assumptions.profile` (proportions scaled off the side render, ±100 mm; the render itself is not to scale, so brochure figures always win). Shows the stock seats or the selected camper modules through the body, plus wheel housings and the floor line. All three pages share a nav that carries the URL selection.
- `assets/models/` — the 14 handover GLBs, kept for the 3D phase. **Origin is mid-body at ground level**, not the front axle (see its README).
- `index.html` (3D) still shows only the Urbania 4400 and loads three.js from `node_modules/` (run `npm install`). Not touched in the rules/engine phase.
- `tools/extract_glb_layouts.js` — reads the furniture boxes out of each GLB (glTF JSON only) into `data/layouts/glb/<id>.json` and checks the walkable aisle (D-AISLE-MIN).
- `tools/import_handover.js` — regenerates `data/vehicles/` and `assets/models/` from the handover.
- `serve.json` — turns off `serve`'s clean-URL redirect, which otherwise drops the `?vehicle=…&modules=…` query between pages.
- `tools/screenshot.js` — Playwright script that screenshots every view and dumps the top-view SVG for exact diffing. See the header comment for usage.

## Rules
- Never invent a dimension. Every number lives in `data/vehicles/<id>.json` with its confidence and source (OEM brochure first; check `data/reference/` and `data/handover/` before assuming something is unknown). UNKNOWN stays `null`. When two sources disagree, the better-evidenced one is primary and the other goes in `alt_estimates`; for India the India brochure wins.
- Both views must be driven off the same JSON so they can never disagree. Shared derivations belong in `js/vehicle.js`, not in a page.
- No vehicle dimension may be hardcoded in a page. Page margins, stroke widths, camera positions and cosmetic modelling details (roof cap, floor slab, light sizes) are not vehicle dimensions and may stay in the page.
- Camper module sizes come from `data/components.json`; never type a module dimension into a page. The lounge preset's sofa/table sizes are the only remaining placeholders in `index.html`.
- Catalog prices are ranges with a `confidence` flag (`web_quoted`, `estimated_from_import`, `estimated`, or `quoted` once a real supplier quote is in hand). Never present an estimate as a quote.
- Light theme only. Clean, minimal, blueprint-style.
- After every visual change, run the dev server and screenshot the page before reporting done. Do not report a fix you have not looked at.
- Toilet must always be fully enclosed. Camper modules use fixed non-overlapping zones with explicit gaps — no running-cursor placement.

## Run
`npx serve .` (uses `serve.json`) (or any static server), then open `/index.html` and `/topview.html`. The pages fetch the JSON, so they must be served over http — opening the files directly (`file://`) will not work.
